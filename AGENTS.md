# Работа с BMI30

- Основная рабочая ветка — `main`. Текущая исходная база и результаты её проверки описаны в `README.md` и `docs/BASELINE_2026-11-12_RU.md`.
- STM32 разрабатывается в корневом проекте; Raspberry runtime — в `Runtime/RaspberryPi/`. Старые копии и вспомогательные патчеры в `HostTools/` не выбирают как исходную базу.
- Сохранять полный состав зависимостей текущего выпуска. Дата отдельного компонента не является основанием для удаления файла из активного манифеста.
- Проверка исходной базы STM32: `python scripts/build_stm32.py`. Она закреплена на исходные хеши и BIN; при разработке нового выпуска обновлять спецификацию и манифесты осознанно, сохраняя неизменяемый предыдущий выпуск.
- Проверка исходной базы Raspberry: `python scripts/verify_raspberry_baseline.py`.
- Политика версий: один календарный месяц — доступный откат; второй месяц — архив восстановления; старше двух календарных месяцев — удаление отдельно сохранённых версий и тегов. Даты отсчитывать по Europe/Prague. Единственная текущая база сохраняется до появления замены. Каталог учёта — `FirmwareReleases/retention-catalog.json`.
- Для версий Git использовать теги `rollback/` и `archive/`; промежуточные рабочие ветки после завершения закрывать. Архивы локальных пакетов находятся в игнорируемом `archives/`, без настроек других приборов в публикуемых исходниках.
- Сборка и проверка репозитория не требуют прошивки или перезапуска приборов. Физические операции выполнять только в явно заданном пользователем объёме.
