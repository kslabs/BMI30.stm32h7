# Проверенный выпуск XM125 0.1.2 для нескольких устройств

Прошиваем готовый выпуск из `FirmwareReleases/XM125/0.1.2/firmware`, без пересборки.
BIN: **103040 байт**, SHA256:
`0d01ec8d3a983f42f8b2657c6279d9335d7e662135e74e400c5263f551d34dc9`.
Исходники этой сборки, лицензии, контрольные суммы и протокол физических проверок
находятся в том же выпуске. `sources.zip` фиксирует исходники на момент сборки;
актуальные инструменты прошивки и настройки находятся в `RadarFirmware/XM125`.

Профиль `presets/early_tag_0.1.2.json` воспроизводит выбранные настройки:
30 Гц, пороги 60/30 мм, включение 20 мс, удержание **1000 мс**, чувствительность
850, качество 25 дБ, адаптация 60 секунд. GPIO0 — открытый сток:
0 замыкает на GND, 1 отпускает вывод. Для штатного подключения используйте
внешнюю подтяжку к 3,3 В и общую землю.

**В BIN остаются первоначальные значения по умолчанию.** После записи на новую
плату обязательно применить профиль. Фон 1175 мм из испытанного экземпляра
не переносится: каждый радар калибруется на своём свободном проходе 600–1800 мм.
Полные резервные копии Flash предназначены для восстановления исходной платы.

## Подготовка

Из корня репозитория: Python 3.10+, `pyserial`, STM32CubeProgrammer CLI.
Для записи готового выпуска SDK и компилятор не требуются.
Для контрольного снятия PEMPTY можно указать OpenOCD и его каталог scripts.
`SERIAL` ниже замените на серийный номер подключённого ST-Link, `COMxx` — на
порт именно настраиваемого радара. Не выбирать первый обнаруженный STM32.
Номер ранее испытанного ST-Link: `066DFF514953667287234159`.

```powershell
python RadarFirmware\XM125\flash.py --check
python RadarFirmware\XM125\flash.py --serial SERIAL --programmer "C:\ST\STM32CubeCLT_1.19.0\STM32CubeProgrammer\bin\STM32_Programmer_CLI.EXE" --backup .tmp\xm125_units\unit01_before.bin
```

Перед записью скрипт проверяет весь выпуск, модель STM32L431 (ID 0x435,
128 КБ Flash), сохраняет полную резервную копию и затем выполняет запись с
проверкой. Область настроек 0x0801F000–0x0801FFFF не входит в образ прошивки.
При использовании OpenOCD добавьте `--openocd ПУТЬ_К_EXE --scripts КАТАЛОГ`.
Скрипт прошивает ELF; он не выполняет массовое стирание памяти.

## Настройка каждой установленной платы

1. Установить радар у одной антенны, направить на вторую. Освободить проход.
2. Подключить USB/UART 115200, 8N1, без RTS/CTS.
3. Выполнить настройку с индивидуальной меткой и новым именем отчёта:

```powershell
python RadarFirmware\XM125\provision.py --port COMxx --label unit01 --empty-passage --report .tmp\xm125_units\unit01_config.json
```

Скрипт проверяет версию и режим GPIO, применяет профиль, запускает CALIBRATE,
ожидает стабильный свободный проход с поступающими измерениями, выполняет
SAVE/LOAD и сравнивает настройки и фон. При неудачной калибровке SAVE не выполняется.
Сам радар не может отличить неподвижного человека от фоновой поверхности во
время калибровки: проход действительно должен быть свободен.

4. Отключить ST-Link, выключить и включить питание. Проверить восстановление:

```powershell
python RadarFirmware\XM125\provision.py --port COMxx --label unit01 --check
python HostTools\rpi_radar\radar_gate.py --port COMxx --watch 10
```

При свободном проходе требуются armed=1, calibrating=0, fault=0 и GPIO0=0.
При подходе/протянутой руке GPIO0=1; при удержании человека фон не изменяется.
После ухода выход возвращается в 0 через 1000 мс устойчивого освобождения.
Проверить и физический уровень/индикатор: поле gpio0 сообщает команду,
а не измеренное напряжение. Для каждой платы отдельно проверить запуск после
отключения питания и отметить результат в журнале монтажа.

В испытанном экземпляре версия 0.1.2 проверена после обычного сброса,
проверка полного отключения питания именно этой версии ещё не записана.
Числовой угол обнаружения в монтаже отдельно не измерялся.

## Репозиторий и проверки

Готовый выпуск: `FirmwareReleases/XM125/0.1.2`.
Исходники и алгоритмические тесты: `RadarFirmware/XM125/src` и `tests`.
Драйвер USB/UART и подготовка карточки портала: `HostTools/rpi_radar`.
Карточка ещё не установлена на Raspberry Pi; её внедрение выполняется отдельно.

```powershell
python -m unittest discover -s RadarFirmware\XM125\tests -p "test_distribution.py"
python RadarFirmware\XM125\tests\run_tests.py
```

Алгоритмические тесты требуют ARM GCC и `unicorn`, `pyelftools` в
`.tmp/xm125_test_deps`, как описано в `README_RU.txt`.
