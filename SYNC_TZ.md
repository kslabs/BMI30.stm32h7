# ТЗ: синхронизация slave по master (RS-485 + TIM15/TIM5)

## 1) Цель
- Быстрый захват фазы при большой ошибке.
- Спокойный lock возле цели: редкие малые шаги коррекции, без "пилы".
- Минимальная девиация в lock (ориентир: около 5–10 мкс или лучше).
- Без постоянного мигания LED в lock-зоне.

## 2) Основной принцип
- Оставить 2 контура:
  - `coarse` — медленная/грубая подстройка частоты через `s_sync_arr_offset`.
  - `fine` — редкие одноразовые импульсы `±1 ARR`.
- Ошибка управления:
  - `e = phase_err_ticks - target_phase_ticks`.
- Управление только по состояниям с гистерезисом:
  - `ACQUIRE` -> `PRELOCK` -> `LOCK`.

## 3) Состояния и переходы

### ACQUIRE (большая ошибка)
- Активен `coarse`.
- Разрешены быстрые шаги, но ограниченные по `max_change`.
- Переключение знака `coarse` только через подтягивание к 0 (без мгновенного перескока).

### PRELOCK (средняя ошибка)
- `coarse` ослаблен (меньше `max_change`, меньшая цель `desired_offset`).
- `fine` пока не выполняет частые шаги.

### LOCK (малая ошибка)
- `coarse` выключен или только мягко стягивается к 0.
- Работает только `fine` как редкая шаговая коррекция по усредненной ошибке.
- Выход из `LOCK` — только по более широкому порогу (гистерезис), чтобы не было дребезга состояний.

## 4) Что запрещено (важно)
- Нельзя делать резкие действия при `zero_cross`:
  - нельзя мгновенно обнулять `s_sync_arr_offset` как реакцию на пересечение нуля;
  - нельзя давать "двойной" или частый импульс `fine` сразу по смене знака.
- Нельзя принимать решение по одиночному шумовому измерению вблизи lock.

## 5) Правильный fine-регулятор в LOCK
- Накапливать signed-ошибку в окне усреднения.
- Вычислять среднюю ошибку `avg_err` только после полного окна.
- Если `|avg_err| <= deadband` — ничего не делать.
- Если `|avg_err| > deadband` — один импульс `s_sync_fine_arr_pulse = ±1` на 1 период.
- После импульса — `refractory` (пауза), в течение которой новые `fine`-импульсы запрещены.

## 6) Рекомендуемые стартовые параметры
- Вход в `LOCK`: 15–20 sample ticks.
- Выход из `LOCK`: 35–45 sample ticks.
- Окно усреднения fine: 100–200 периодов sync (порядка 0.5–1.0 с).
- Deadband fine: около 1–2 `edge_window`.
- Частота шагов fine в lock: ориентир 0.5–2 шага/с.

## 7) LED-индикация
- LED ON только в `ACQUIRE/PRELOCK` (активный coarse).
- LED OFF в `LOCK`.
- Постоянное мигание LED вблизи цели — признак дребезга между состояниями (исправляется гистерезисом).

## 8) План реализации (после отката)
1. Восстановить файл из архива (baseline).
2. Ввести явный state machine (`ACQUIRE/PRELOCK/LOCK`) и гистерезис вход/выход в `LOCK`.
3. Оставить существующий coarse, но запретить резкие zero-cross действия.
4. Сделать fine по усреднению в окне + deadband + refractory.
5. Проверить LED-логику по состояниям.
6. После каждого шага выполнять BUILD+FLASH.

## 9) Критерии приемки
- Нет постоянного мигания LED в lock.
- В lock нет частых скачков коррекции.
- Девиация фазы стабильно малая и без выбросов, относительно текущей цели.
- При выходе из lock (большая ошибка) захват остается быстрым.
