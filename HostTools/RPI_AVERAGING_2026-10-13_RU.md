# Дополнительное усреднение Raspberry — S07 и M02, 13.10.2026

Последующее обновление: [диапазон 1–12, релиз 2026-10-13-163828 на USB и eMMC обеих плат](RPI_AVERAGING_12_2026-10-13_RU.md).
Ниже сохранён протокол первоначального внедрения 1–8.

Позднее в тот же день USB и eMMC обеих плат синхронизированы, выполнены реальные
загрузки с USB. Единый идентификатор релиза — **2026-10-13-153432**, пакет
**2026-10-13-1534**. Текущий итог: [протокол синхронизации](RPI_MEDIA_SYNC_2026-10-13_RU.md).
Состояние eMMC и настройки ниже относятся к первоначальному внедрению.

Установлен полный пакет Raspberry **2026-10-13-1534** на S07
(`BMI30-C9775FBAE`) и M02 (`BMI30-E29805C7C`). Обе системы работают с eMMC
`/dev/mmcblk0p2`. Прошивка STM32 остаётся 1.2.56.

## Поведение

- **3 Operating Mode → Default averaging → Raspberry averaging**: 1–8.
- STM32 сохраняет свой диапазон 8/16/24/32/40/48/56/64.
- Raspberry хранит в RAM последние N полученных пакетов отдельно для каждого
  канала и чётности. Скользящая сумма обновляется добавлением нового и
  вычитанием самого старого пакета. Обе фазы канала должны накопить полное окно
  до передачи результата детектору; затем расчёт обновляется на каждом пакете.
- Усреднение применяется перед существующим входным сглаживанием. Детектор
  и осциллограф получают одинаковые обработанные данные.
- При N=1 исходные отсчёты проходят без дополнительного усреднения и без
  выделения кольцевых массивов. Полные/raw режимы также проходят без него.
- Изменение глубины, STM32-усреднения, потока, поколения обработчика или длины
  отсчётов сбрасывает историю; нарушение последовательности пакетов сбрасывает
  накопленное окно. Каналы и противоположные фазы не смешиваются.
- Save Only сохраняет оба параметра для следующего запуска. Save and Apply
  сохраняет и применяет их в работающем ядре.
- На осциллографе вместо редактора показано `STM32/Raspberry`. Надпись
  отцентрирована в ячейке по вертикали и горизонтали.
- Сырые записи Player сохраняют исходные пакеты и поле `rpi_avg_n`.
  При офлайн-построении записи применяется её сохранённая глубина. Для старых
  записей без этого поля используется 1.

## Ресурсы и влияние на сигнал

Изолированный замер самого алгоритма на обеих работающих Raspberry:

| Вход | Окно | S07, мкс/пакет | M02, мкс/пакет | RAM четырёх историй |
|---|---:|---:|---:|---:|
| 200 отсчётов | 8 | 10.59 | 10.52 | 32 000 байт |
| 600 отсчётов | 8 | 12.67 | 12.62 | 96 000 байт |

Даже при 100 пакетах/с средняя дополнительная вычислительная стоимость
для 200 отсчётов составляет около 0.11% одного ядра. Это стоимость усреднения,
а не суммарная нагрузка всех служб устройства.

Для независимого шума теоретический выигрыш SNR равен sqrt(N):
2 → 1.41 раза / 3 дБ, 4 → 2 раза / 6 дБ, 8 → 2.83 раза / 9 дБ.
Синтетический тест подтвердил снижение независимого шума. Коррелированная
помеха, изменение фазы/формы сигнала и быстрый проход могут уменьшить выигрыш.
Короткий сигнал разбавляется предыдущими пакетами без метки. Перекрывающиеся
окна также делают последовательные подтверждения зависимыми.

При наблюдавшихся примерно 17 пакетах/с на канал и STM32=24 одна чётность
обновляется примерно каждые 118 мс. Окно Raspberry=8 добавляет около 412 мс
среднего возраста данных; полная временная ширина двухступенчатого окна
близка к 0.94–0.96 с. Обновление после каждого пакета не устраняет эту ширину.
Это оценка по измеренной частоте, а не гарантия времени срабатывания.

Статистика реальных размеченных проходов метки до/после не собиралась;
улучшение вероятности обнаружения и уровня ложных срабатываний физическим
сравнением пока не подтверждено.

## Проверка и состояние

- 10 тестов: все окна 1–8, раздельные ADC/фазы, точное скользящее среднее,
  заполнение перед детекцией, смена контекста/длины, пропуск и wrap sequence,
  bypass=1/raw, валидация, сохранение параметров реальными функциями портала,
  снижение независимого шума и разбавление короткого сигнала.
  Тесты прошли локально и на обеих Raspberry.
- Все окна 1–8 проверены через API работающего ядра. Истории заполнялись;
  детектор продолжал выдавать результаты. Новых sequence gaps, CRC и ошибок
  подтверждения при этих проверках не было.
- Через браузер на обеих платах сохранено окно 8. После реального перезапуска
  `bmi30-core` оно восстановилось, все четыре истории достигли 8, обработчик
  выдавал результаты; фиксированные RX-сдвиги сохранены.
- Затем тестовый режим возвращён к 24/1. На момент финального API-аудита
  пользователь выбрал S07 **16/4**, M02 был **24/1**. Пользователь продолжает
  проверку и меняет окна; на последнем скриншоте S07 уже **16/6**. Эти снимки
  не следует считать неизменяемой текущей конфигурацией.
- SHA256 активного кода и установленного портала проверены; полный пакет на
  обеих платах проходит штатный `--validate`. Фреймы осциллографа доступны,
  USB и обработчик живы, новых ошибок за финальное наблюдение нет.
- Центрирование проверено в Chrome на обоих устройствах. На S07 отклонение
  центра текстового диапазона от центра ячейки было менее 0.4 CSS-пикселя.

Активация пакетов сохраняла постоянные файлы конфигурации. Save and Apply
Operating Mode сохраняет весь этот раздел; на S07 он также синхронизировал
host JSON с показанными в портале DC-таймерами 20/15/10 с (ранний host JSON
содержал 30/20/10 с). Настройки детекции, TX/RX-фазы и звука по сравнению с
исходным снимком не изменились; служебные даты сохранения обновлены.
