# M02: оценка шума max(среднее, P95), 15.10.2026

На M02 `BMI30-E29805C7C`, CM5 serial `490df72e29805c7c`, установлена и
проверена версия Raspberry `2026-10-15-1455`, firmware manifest
`2026-10-15-145847`. Рабочая корневая система — USB `/dev/sda2`.
Активный engine:
`/home/techaid/Documents/host/bmi30_active_runtime/project/host/BMI30.200.py.2026-10-15-1455`.

## Изменение

Пространственное измерение осталось прежним: максимум абсолютного произведения
в выбранной области вне исключаемой зоны вокруг максимального импульса,
с круговой индексацией. Сохранена текущая область **66%**.

В каждом канале отдельно сохраняется временная история этих измерений.
Вместо одного арифметического среднего теперь используется
**max(среднее, P95)**, где P95 — 95-й процентиль с линейной интерполяцией.
Среднее остаётся нижней границей оценки, в том числе для очень редкого
большого выброса, который сам P95 мог бы проигнорировать.
Мгновенная проверка S/N текущего пакета сохранена.

Окно осталось **5 с**. Это длительность скользящей истории, а не задержка
обнаружения. Оценка обновляется с каждым поступающим измерением.
На странице **2 Tag Detection** показан метод только для чтения
`Noise estimator: max(mean, P95)`; прежний параметр переименован в
`Noise history window`, диапазон **0.05–10 с**, шаг **0.05 с** сохранён.
Процентиль пока фиксирован на 95.

Коэффициенты low/high **3 / 1.5**, AUTO=off, по 5 подтверждений,
STM32 avg16 / Raspberry avg8, сглаживание4 и остальные настройки сохранены.
Формулы коэффициента, порога и геометрические проверки не менялись.
Существующая кривая интерполирует эффективный коэффициент по оценке шума:
число эффективного коэффициента может следовать новой оценке, хотя заданные
пользователем коэффициенты остались прежними.

API и точные снимки решений содержат `noise_estimator`, `noise_mean`,
`noise_p95`, `noise_samples`. Совместимое поле `noise_avg` теперь означает
итоговую оценку max(среднее,P95); отдельная диагностика `snr_avg` сохранила
прежний смысл. В Player compact status также сохраняются новые сведения,
чтобы последующие записи меток можно было интерпретировать.

## Почему пока 5 секунд

В приближённом анализе предыдущей десятиминутной фоновой записи вариант
P95 с окном1с разрывал 12 из 26 сохранённых цепочек событий, а с окном5с —
17 из26. Это сравнение исходных цепочек, а не полный повтор детектора;
другая цепочка могла бы возникнуть позже. Оно не доказывает оптимальность
5с или снижение количества тревог на17/26.

Короткое окно быстрее возвращает чувствительность после изменения фона,
но быстрее забывает помеху. Длинное дольше сохраняет повышенную оценку и
может ухудшить обнаружение слабых меток. Для первого рабочего варианта
оставлены5с; после записей реальных проходов имеет смысл сравнить1,2 и5с.
Исходное наблюдение описано в `NOISE_OBSERVATION_2026-10-15_RU.md`.

## Проверки

- На M02 прошли **48 тестов**:10 новых для статистики и её подключения к
  реальному детектору,12 для области,15 для ширины,11 для усреднения.
  Проверены независимость каналов, границы истории и её изменение,
  сброс, выбросы/нечисловые значения, отказ и последующее подтверждение
  реальным обработчиком. AST-сравнение подтверждает неизменность
  пространственного измерения, мгновенной проверки и прежних формул.
- Изолированное измерение на M02,500 повторений: медиана нового расчёта
  **0.136 мс** для125 значений и **0.149 мс** для250; P95 времени
  соответственно0.180 и0.159мс. Это стоимость функции, а не всего процесса.
- После установки20 снимков API примерно за10с подтвердили
  `noise_avg == max(noise_mean, noise_p95)` на обоих каналах,117–125
  измерений в истории, работу выбранного engine и сохранность настроек.
  Получено **486** новых результатов обработчика, прирост
  gap/dup/CRC/magic/ACK, переполнений и задержек>100мс — **0**.
  Кадры обоих каналов доступны, область66%.
- Установленный портал отрисован его фактической серверной функцией:
  метод, область66 и окно5 показаны корректно. Проверен синтаксис всех
  7 встроенных скриптов портала и3 скриптов осциллографа.
  Проверка не создавала сессию входа; визуальная проверка браузера в эту
  установку не входила.
- Конфигурационные файлы сохранены при установке; контрольный JSON не
  менялся при последующей проверке. Обновлён журнал версий M02 и выполнена
  штатная синхронизация таблицы:162 строки,14 столбцов,rc=0.

Короткая проверка подтверждает исправность установленного кода. Нового
длительного фонового опыта после установки и проходов реальных меток ещё
не было; снижение ложных тревог и сохранение чувствительности пока не доказаны.
