# Системный LED: выбранный фотодатчик, версия 1.2.48

Исправлено перекрытие удалённого источника собственным фотодатчиком.
На S10 до исправления источник был M01 (ID 1), удалённое состояние было активно,
но собственный активный датчик имел приоритет и давал жёлтый RGB (75, 37, 0).

Правила 1.2.48:

| Настройка 0x44 | Источник системного LED |
| --- | --- |
| 255 (без привязки) | Собственный датчик; жёлтый на slave, зелёный на master |
| Собственный ID | Собственный датчик |
| Другой ID 0..31 | Только указанный датчик; активность даёт фиолетовый |

Если выбран удалённый датчик и он не активен, собственный датчик не влияет на LED:
показывается обычный статус роли/связи/ошибки. TX-модуляция яркости сохраняется.
Публикация собственного датчика по RS485/USB не изменена. Поведение при устаревшем
удалённом статусе не изменено: сохраняется последнее принятое состояние.
Привязка остаётся runtime-настройкой; хост повторяет её после reset/reconnect.

Проверка на S10 через SWD без остановки MCU, при собственном датчике HIGH:

- После запуска хост отправил control OUT 0x44, wValue=1. Аудит:
  setup_count=1, cmd_count=1, cmd_len=2, cmd_value=1, applied=1.
- M01 HIGH: удалённый источник активен; RGB (128, 0, 80) и другие значения
  фиолетового в ходе TX-breathe, вместо прежнего жёлтого.
- Временный source=255: RGB (2, 1, 0), локальный жёлтый при низкой яркости.
- Временный source=10: RGB (158, 79, 0), явный собственный источник.
- Временный source=12 при его LOW: RGB (1, 1, 1), базовый белый;
  собственный HIGH не включает жёлтый.
- После теста восстановлен source=1 (M01).

Временные варианты источника проверены записью его RAM-параметра через SWD;
исходная привязка M01 после перезапуска подтверждена именно USB-аудитом.
Диагностические счётчики 1.2.47 сохранены; см. OPTIC_USB_DIAGNOSTICS_RU.md.
