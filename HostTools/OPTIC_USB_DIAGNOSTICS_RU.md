# Проверка настройки системного LED через USB

Диагностическая сборка 1.2.47 сохраняет поведение 1.2.46 и добавляет в UART
ответ `OPTIC` аудит команды `0x44 SET_OPTIC_REACTION_SOURCE`.

- `usb_cmd_total`: число всех непустых команд, попавших в общий USB обработчик.
- `optic_setup_count`: число USB SETUP с `bRequest=0x44`, попавших в обработчик класса.
- `optic_setup_type/value/index/len`: последние bmRequestType, wValue, wIndex, wLength.
- `optic_cmd_count`: число команд `0x44` в общем обработчике, включая короткие.
- `optic_cmd_len`: длина последней команды вместе с opcode.
- `optic_cmd_value`: первый байт параметра; `4294967295` означает отсутствие параметра.
- `optic_cmd_applied`: последнее применённое через USB значение;
  `4294967295` означает, что применение через USB ещё не происходило.
- `optic_cmd_age_ms`: время с последней команды `0x44`; `4294967295`, если её не было.
- `optic_src`: текущий источник LED, в том числе после ручного `OPTSRC`.

Счётчики сбрасываются при перезагрузке STM32. UART `OPTSRC` не увеличивает USB-счётчики.
Опрос `OPTIC` не меняет настройку. Для Bulk OUT `optic_setup_count` не увеличивается;
`optic_cmd_count` увеличивается. Для control OUT увеличиваются оба счётчика.

Для реакции S11 на M01 отправить в USB S11 либо Bulk OUT `44 01`, либо
control OUT `bmRequestType=0x40, bRequest=0x44, wValue=1, wIndex=0, wLength=0`.
При control OUT с телом передать один байт `01` (без повторения opcode).
Проверить `optic_cmd_value=1`, `optic_cmd_applied=1`, `optic_src=1`.
При отключении ожидается `255`. При неправильном ID `32..254` существующий
обработчик преобразует его в `255`; аудит сохраняет исходный параметр.

Сначала снять счётчики, затем сохранить настройку в UI, затем снять их повторно.
Рост общих USB-команд при неизменных счётчиках `0x44` означает, что в этих
обработчиках команда не зарегистрирована; он не доказывает содержимое исходящей
передачи хоста без его журнала или USB-трассы.

Данные датчиков RS485 передаются хосту независимо от настройки LED `0x44`.
`0x43` читает датчики выбранного ID, `0x30` возвращает таблицу статусов;
эти запросы не изменяют источник системного светодиода.
