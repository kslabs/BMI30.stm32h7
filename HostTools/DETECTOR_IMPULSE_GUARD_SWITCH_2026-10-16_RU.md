# Управляемая проверка одиночного импульса

На M02 установлен полный Raspberry-пакет `2026-10-16-1743`
(манифест `2026-10-16-174347`). Устройство проверено по hostname
`BMI30-E29805C7C`, serial `490df72e29805c7c`, активный root `/dev/sda2`.
STM32 и другие устройства/носители не обновлялись.

## Управление

В «Обнаружение меток → Фильтрация детекции» перед burst-gate добавлена общая
галочка **«Защита от одиночного импульса»** (`impulse_guard_enabled`).
Изменение активируется обычной кнопкой сохранения и применения к Core.

- Снята: основной детектор использует усреднение Raspberry. Исходные окна
  дополнительно не копируются для этой проверки, не передаются worker и не
  пересчитываются с исключением отдельных пакетов. Эта защита не запрещает
  основной результат. В API `dual.enabled=false`, `dual.mode=averaged_only`;
  её диагностический результат — `enabled=false, allowed=true, reason=disabled`.
- Установлена: после усреднения работает прежняя дополнительная проверка
  влияния каждого исходного пакета. Основной результат и проверка должны
  пройти. Отсутствующее, устаревшее или явно отключённое доказательство не
  разрешает событие при включённой защите.

После установки и итоговой проверки **галочка снята**. Это также значение по
умолчанию для конфигурации без нового ключа. Разнообразие семплов остаётся
отдельной настройкой, сейчас 0. Четыре подтверждения на обе антенны, усреднение
16/8, частота 200 Гц, пороги и другие текущие параметры сохранены. Область
измерения шума на момент установки — 70%; это текущее значение пользователя,
его не возвращали к прежним 66%.

Ноль разнообразия отключал только условие разных номеров семплов; дополнительная
проверка исходных пакетов в предыдущей версии продолжала работать. Это не
доказывает, что именно она вызвала наблюдавшееся ухудшение чувствительности.
Теперь её можно отдельно включать и выключать для сравнения.

## Реализация

Значение передаётся в неизменяемых метаданных запроса worker. Отключение
обходит сам пересчёт, а не только игнорирует запрет после его выполнения.
Переключение очищает обе цепочки/HOLD и меняет поколение worker, поэтому
старые результаты не достраивают новую цепочку. Фоновая история шума не
сбрасывается новым переключателем.

Сохранение через портал и core согласует верхний ключ конфигурации с
`tag_detection.impulse_guard_enabled`. Для checkbox есть скрытое значение 0:
снятая галочка явно сохраняется как false. API частичного изменения не
сбрасывает настройку, если ключ не передан.

Усреднение, свежие пары, burst-gate, common-mode, ширина основания и остальные
условия основного детектора сохранены. AutoFreeze сохраняет обе антенны,
линии шума, время в заголовке и параметры события. Подсказка шума показывает,
что защита выключена, без устаревших значений её проверки.

## Проверка

- 10 новых тестов: обход отсутствующего/запрещающего доказательства при OFF,
  обязательное действующее доказательство при ON, сохранение основных
  ограничений, переключение/очистка цепей и worker, отсутствие второго
  вычислительного пути при OFF, checkbox/form/API и загрузка конфигурации.
- 66 регрессионных тестов прошли: разнообразие семплов, свежие пары,
  burst-gate, исходная защита, шум, ширина основания и metadata AutoFreeze.
- При разнообразии 0 и защите OFF реальные функции принятия решения на 610
  тестовых кадрах дали те же события, счётчики подтверждений, HOLD и позиции,
  что основной путь версии `1605` до добавления разнообразия. Это проверка
  программных функций с синтетическими входами, не реального прохода метки.
- Настоящий FIFO worker/CM pairer обработал одинаковые данные дважды:
  26 результатов с OFF, 26 с ON. Вызовов исходной проверки соответственно
  0 и 26. Основные произведения, уровни и позиции пиков совпали. Обе антенны
  и метаданные поколения/источника сохранены.
- JavaScript: readout AutoFreeze, время, обе осциллограммы, шум, разнообразие,
  выключенная защита и её русская подсказка; 14 проверок транспорта/отрисовки.
- Живой M02 после установки: +472 результата worker за 10 секунд; дельты
  gap/duplicate/CRC/magic/ACK/overflow и задержек >100 мс в этом интервале — 0.
  Счётчики дополнительной проверки `[0,0]`, режим `averaged_only`.
  Принято одно событие верхней антенны с пиками `[97,98,97,97]` и сохранённым
  `impulse_guard.reason=disabled`; происхождение этого события не определялось.
- Chrome: русская галочка видима и снята, подсказка объясняет оба режима;
  ошибок консоли нет. Исходный английский язык браузера восстановлен.
- Итоговое чтение: защита false, разнообразие 0, подтверждения 4/4,
  счётчики проверки `[0,0]`. Позднее в общей статистике были два эпизода
  обработки/доставки >100 мс (максимум около 202 мс); выключение защиты не
  устраняет само по себе все задержки планирования/доставки.

На работающем устройстве для проверки не включали защиту обратно и не
меняли пользовательские параметры: пользователь продолжал настройку.
Сохранение и оба состояния проверены реальными функциями offline; рабочий
runtime проверен с выключенной защитой. Физические проходы и восстановление
дальности в этом изменении не подтверждены.
