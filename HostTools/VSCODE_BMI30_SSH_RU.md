# Автоматическое подключение VS Code к BMI30

Настроено 29.09.2026 на Windows-компьютере TECHAID51.

Вход без пароля проверен на всех пяти устройствах: S10 `BMI30-D5EB8F26C`,
S11 `BMI30-D5507EDFC`, S12 `BMI30-27448D72B`, S13 `BMI30-7AA5CED27`,
M01 `BMI30-05AB38E6A`. На S10 публичный ключ сохранён на USB и внутренней eMMC;
остальные четыре на момент итоговой проверки загружены с eMMC.

При открытии этого локального проекта задача `BMI30: auto-connect all boards`
ищет устройства с именами `BMI30*` в непосредственно подключённых частных IPv4
подсетях. Проверка повторяется раз в 60 секунд. Каждая доступная и авторизованная
плата открывается в новом отдельном окне VS Code, каталог `/home/techaid/Documents`.
В пределах одного запуска наблюдателя одна плата открывается один раз; закрытое
пользователем окно не навязывается повторно каждую минуту. При запуске скрипт
проверяет уже открытые подключения по выводу `code --status` и пропускает их.
Если редактор не смог выдать этот список, после перезапуска наблюдателя возможны
дополнительные окна. Уже открытые окна скрипт не закрывает и не заменяет.

Наблюдатель запускается задачей при открытии проекта, а не при входе в Windows.
Остановить его: **Terminal → Run Task → BMI30: stop automatic connections**.
Запустить вручную: **Terminal → Run Task → BMI30: auto-connect all boards**.
Настройка автоматических задач включена только в этом проекте. Задача запускает
скрытый фоновый процесс; его журнал — `%LOCALAPPDATA%\BMI30-RemoteSSH\watch.log`.
Повторный запуск не создаёт второго наблюдателя. После закрытия всех процессов
VS Code наблюдатель завершится при следующем цикле проверки.

## Имена и смена IP

Обнаружение использует открытый GET `/api/status` на локальном HTTP-порту 80.
На этом компьютере `.local` не разрешался, поэтому mDNS не является обязательным.
Поиск ограничен непосредственно подключёнными частными подсетями /22–/32;
более широкие подсети пропускаются. Для новых прошивок без веб-интерфейса этот
способ обнаружения потребуется дополнить.

SSH-алиас равен имени устройства. Адрес `HostName` обновляется автоматически,
а `HostKeyAlias` остаётся именем платы. Изменение IP не требует повторного
ввода пароля. Во время смены IP действующая SSH-сессия может оборваться;
после обновления адреса повторное подключение VS Code использует новый IP.
Если редактор уже прекратил попытки, нажать **Reconnect** в его окне.

Перед первым автоматическим открытием скрипт проверяет доступ по ключу и
соответствие результата SSH-команды `hostname` имени, найденному через HTTP.
Одинаковые имена на разных IP не открываются автоматически. Непроверенные или
изменившиеся серверные ключи автоматически не принимаются.

## Постоянный доступ этого компьютера

- Закрытый ключ: `%USERPROFILE%\.ssh\id_ed25519_bmi30`.
- Публичная часть: `%USERPROFILE%\.ssh\id_ed25519_bmi30.pub`.
- На плате публичная часть хранится в `/home/techaid/.ssh/authorized_keys`.
- Для автоматического входа ключ без парольной фразы; его Windows ACL разрешает
  доступ владельцу. Закрытый ключ не передаётся на платы и не хранится в Git.
- OpenSSH выбирает ключ через `IdentityFile`, загружать его вручную или запускать
  `ssh-agent` не требуется. Публичная часть добавляется без удаления других ключей.

Новая плата требует первоначального разрешения доступа. В VS Code выполнить:
**Terminal → Run Task → BMI30: authorize this computer on new boards**.
В терминале один раз ввести пароль пользователя `techaid`. При первом контакте
с новым сервером OpenSSH также попросит подтвердить его ключ; сверить отпечаток
с устройством. Уже авторизованные платы пропускаются. После этого наблюдатель
откроет новую плату при следующей проверке. PowerShell-задача авторизации после
успешной установки ключей также запускает наблюдатель, если он ещё не работает.
Остановка выполняется задачей `BMI30: stop automatic connections`.

После переустановки ОС платы или загрузки другого независимого системного диска
в его `authorized_keys` тоже должна быть установлена публичная часть ключа.
При замене компьютера создаётся его собственный ключ и разрешается отдельно.

## Файлы настройки и ручные команды

`%USERPROFILE%\.ssh\config` включает автоматически формируемый `bmi30_config`.
Проверенные серверные ключи хранятся отдельно в `bmi30_known_hosts`.
Инвентаризация и настройки скрипта: `%LOCALAPPDATA%\BMI30-RemoteSSH`.
Резервная копия пользовательских настроек VS Code сохраняется туда при `setup`.
Ожидание первичного подключения Remote SSH установлено в 60 секунд: короткое
ожидание вызывало ошибки при одновременном открытии нескольких новых окон.

Из корня локального проекта:

```powershell
py -3 HostTools/bmi30_remote_ssh.py discover # найти платы и обновить адреса
py -3 HostTools/bmi30_remote_ssh.py check    # проверить вход без пароля и hostname
py -3 HostTools/bmi30_remote_ssh.py enroll   # разрешить доступ новым платам
py -3 HostTools/bmi30_remote_ssh.py watch    # наблюдать и открывать все платы
```

Первоначальная настройка другого Windows-компьютера с Python 3:

```powershell
code --install-extension ms-vscode-remote.remote-ssh
py -3 HostTools/bmi30_remote_ssh.py setup
py -3 HostTools/bmi30_remote_ssh.py enroll
```

`setup` предполагает обычный JSON в пользовательском `settings.json`; если файл
содержит комментарии JSONC, их нужно учесть перед запуском установщика.
Пути к OpenSSH и VS Code определяются локально. В коде нет паролей и жёсткой
привязки к сегодняшним IP четырёх устройств.

Поиск и установка ключей не меняют прошивку, службы детектора, ADC/DMA или USB.
Сам Remote SSH устанавливает VS Code Server на плате; нагрузка редактора и
расширений зависит от открытого проекта и запускаемых пользователем задач.

Официальная документация: [VS Code Remote SSH](https://code.visualstudio.com/docs/remote/ssh),
[автоматические задачи VS Code](https://code.visualstudio.com/docs/debugtest/tasks).
