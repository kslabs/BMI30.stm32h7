# Исправление номера Raspberry Pi — 2026-10-23

Номер устройства берётся из аппаратного serial текущей Raspberry Pi. Hostname,
machine-id, номер STM32, адрес RS485 и IP не используются вместо него.
Собственный номер публикуется в API и передаётся STM32 для группового обмена.

В групповой таблице номер Raspberry Pi и STM32 UID разделены. Подтверждённое
соответствие хранится по аппаратному UID, независимо от свежести телеметрии.
При позднем появлении данных обновляется уже существующий заголовок. Чужой
номер нельзя присвоить колонке только из-за совпадения IP или RS485 ID.

До первого получения номера удалённой Raspberry Pi выводится `RPI —`;
STM32 UID вместо него не подставляется. Локальный номер читается непосредственно
на самой Raspberry Pi, поэтому доступ к роутеру или интернету для него не нужен.

Для S12 правильное соответствие: Wi-Fi / Raspberry Pi `BMI30-27448D72B`,
STM32 `556E5FA3B`.

## Установка на доступное устройство

Распаковать архив `BMI30-RPi-identity-2026-10-23.tar.gz` на целевой Raspberry Pi
и перейти в каталог `bmi30-rpi-identity`. Сначала проверить план:

```sh
sudo python3 -W ignore::SyntaxWarning install_rpi_identity.py --expected-id BMI30-27448D72B
```

Установить исправление:

```sh
sudo python3 -W ignore::SyntaxWarning install_rpi_identity.py --expected-id BMI30-27448D72B --apply
```

Для каждой другой платы указывается её собственный номер:

| Устройство | `--expected-id` |
|---|---|
| M01 | `BMI30-05AB38E6A` |
| S11 | `BMI30-D5507EDFC` |
| S12 | `BMI30-27448D72B` |
| S13 | `BMI30-7AA5CED27` |

Установщик сверяет номер с аппаратным serial до изменения файлов. Он определяет
активный исходник по `host/bmi30_split_active_version.env`, проверяет совместимость
всех копий портала и сохраняет резервную копию в `/var/backups/bmi30-rpi-identity/`.
Затем обновляет только портал и перезапускает `bmi30-hotspot-info`. PID измерительного
процесса и контрольные суммы его исходников и настроек должны сохраниться.
Ошибки проверки вызывают восстановление исходных файлов портала.

После установки `/api/status` должен возвращать аппаратное имя устройства и
`"rpi_identity_version": "2026-10-23"`. Для обновления старых Raspberry Pi, на которых
нет требуемой структуры кода, установщик завершится до записи файлов.

Исправление номера не является диагностикой причины отказа подключения Wi-Fi.

## Проверка при сборке

`build_rpi_identity_release.py` создаёт отдельный пакет исправления, контрольные
суммы, diff и исправленный исходник портала для просмотра. Он не изменяет
существующие архивы и не устанавливает обновление на подключённые устройства.
