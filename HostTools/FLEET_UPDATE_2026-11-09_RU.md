# Четыре прибора BMI30 обновлены — 9 ноября 2026

Рабочий срез после физической загрузки S13 с собственной eMMC.
STM32 всех четырёх приборов обновлены и проверены. M01, S11, S12 и S13 работают
с Raspberry **2026-11-06-151000** на собственной eMMC; полный native gate S13 прошёл.
Физическую проверку повторной загрузки USB2 пользователь отложил:
**«Проверить загрузку позже»**. S11 оставлен работающим с native eMMC,
перезагрузка для этой проверки не выполнялась.

native boot, полученное после выключения, удаления USB и повторного запуска.

У S11 [финальный native gate](../.tmp/update-devices-20261109/110-native-final-gate-rechecked.json)
подтвердил версии, идентичность, службы и поток/worker без новых ошибок.
В этом историческом срезе сетевой API вернул `Internet.ok=false`, поэтому сводный `all_checks_pass=false`.
При этом прямое соединение с проверкой TLS успешно, Agent — approved и свежий
в текущей загрузке. Это отдельное расхождение статуса API, не отказ прошивки
и не подтверждённый отказ TLS.

У S13 выявлен существующий нечитаемый сектор STM32 №6
`0x080C0000..0x080DFFFF`; дальнейшие чтения этого участка прекращены.
Полный Flash backup S13 **не заявляется**. Полностью сохранён собственный
изменяемый диапазон `0x08000000..0x0805FFFF` — три сектора, **393216 байт**.
BIN и собственный rollback ограничены этим диапазоном. Сектора 3–5, ранее
прочитанные как нули, и сектор 6 не записывались; NVM сектора 7 прочитана
отдельно и совпала до/после прошивки. Option bytes и роли не записывались.
CLI останавливает CPU на время каждой операции; непрерывная остановка между
вызовами не заявляется.

**USB2**, serial `25072913740186`, root PARTUUID `9b667395-02`:

Успешная загрузка после этих исправлений **ещё не подтверждена**;
по явному решению пользователя она будет проверена позже.

Автоматическая проверка отклонила прежнюю попытку создать новые параметры AP;
эта запись не выполнена. Затем пользователь явно выбрал **«Оставить только
известные Wi-Fi сети»**. Новый HotSpot/AP и пароль не создаём. Для USB2 требуется
только физическая проверка: [STA-only исправление применено](../.tmp/update-devices-20261109/110-USB2-STA-fixed.json)
к трём файлам — adopter, его policy-config и drop-in службы hotspot.
Проверка подтвердила сохранение 31 известного STA-профиля, отсутствие записи
паролей/AP, импорта Agent/роли и активации live NetworkManager.
[Snapshot собственных актуальных настроек S11 обновлён](../.tmp/update-devices-20261109/110-USB2-own-snapshot-refreshed.json),
native-настройки не изменялись; USB размонтирован.
[Предшествующая read-only диагностика](../.tmp/update-devices-20261109/110-S11-returned-USB-AP-plan.json)
сохраняет историю; её план создания AP больше не является разрешённым действием.

## Известные Wi-Fi сети

По выбору пользователя объединены только сохранённые STA-профили четырёх приборов.
[Исходные 153 записи](../.tmp/update-devices-20261109/known-wifi-union-installed-before-S13-native.json)
дали **14 уникальных профилей**: 12 роутерных с автоподключением и 2 BMI30 peer-STA
с ручным подключением; пропущенных записей — 0, новых AP — 0.
Все 14 установлены и прочитаны обратно на native M01/S11/S12 и обоих USB;
source snapshots USB обновлены и проверены. Файлы имеют режим `0600`, активные
UUID соединений не менялись, активация другого подключения не запрашивалась.
После загрузки eMMC [те же 14 профилей установлены на native S13](../.tmp/update-devices-20261109/known-wifi-S13-native-union-installed.json):
повторный сбор 195 записей дал тот же набор, 0 пропусков, активный UUID сохранён.
Пароли и содержимое профилей в локальные отчёты не выводились.

В режиме 3 свежий поток без роста detector worker является штатным состоянием.
Рост worker требуется в режиме 6 с активной детекцией; переключать пользовательский
режим ради проверки нельзя. Изменения настроек M01, подтверждённые пользователем
во время работы, сохранены. Пароли, ключи, токены и сырые NVM-дампы в этот отчёт
не включены. Краткие проверки не являются испытанием дальности или вероятности
обнаружения меток.
