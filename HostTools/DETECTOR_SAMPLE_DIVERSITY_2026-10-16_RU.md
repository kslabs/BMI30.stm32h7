# Разнообразие номеров семплов при подтверждении

На M02 установлен полный Raspberry-пакет `2026-10-16-1712`, версия манифеста
`2026-10-16-171216`. Проверены hostname `BMI30-E29805C7C`, serial
`490df72e29805c7c` и активный USB root `/dev/sda2`.
Новая настройка находится в «Обнаружение меток → Настройки решения по каналам»
рядом с числом подтверждений и допуском фазы. Название:
**«Разнообразие номеров семплов»**, API/config: `confirm_sample_diversity`.

## Значения и компромисс

Общий параметр применяется независимо к окну каждой антенны. При C
подтверждениях значение k>0 требует не менее k+1 **разных целочисленных
номеров семпла пика** среди последних C последовательных принятых кандидатов.
Это число разных позиций, а не размах max−min и не число переходов между ними.

| k | Требование при пяти подтверждениях |
|---|---|
| 0 | Проверка выключена; пять одинаковых позиций разрешены |
| 1 | Минимум два разных номера |
| 2 | Минимум три разных номера |
| 3 | Минимум четыре разных номера |
| 4 | Все пять номеров разные |

Например, `[92,92,92,92,93]` проходит при 1; `[90,92,90,92,90]` не проходит
при 2, хотя размах равен двум семплам. `[90,91,92,91,90]` проходит при 2.

Рекомендуемая первая проба — **1**: отвергать строго неподвижный пик,
допуская единственное изменение номера на один семпл. Движение метки ещё не
гарантирует изменения дискретного максимума в каждом коротком окне,
поэтому более строгие значения требуют проверки реальных проходов.

**По умолчанию и после установки оставлено 0.** Во время проверки API значение
1 включалось временно на 25 секунд; затем восстановлено 0. Конфигурация на
диске не изменялась. Реальные метки и дальность на этом этапе не проверялись.

## Поведение алгоритма

- Усреднение STM32/Raspberry, пространственный avg9, амплитудные/шумовые
  пороги, common-mode и проверка влияния одиночного пакета сохранены.
- При блокировке разнообразием окно сдвигается на одного свежего кандидата.
  Старые номера не накапливаются вне последних C кадров. Пропуск кандидата,
  разрыв входных кадров и выход за максимальный фазовый допуск обрывают цепь.
- Новая проверка допускает старт события только после выполнения всех
  существующих условий. Она не добавляет фиксированное число кадров:
  подходящая цепь срабатывает на C-м кандидате. При недостаточном
  разнообразии ожидание продолжается, возможно до полного подавления события.
- Уже принятое событие удерживается по существующим правилам HOLD; проверка
  разнообразия не режет его на повторные события после начала сигнализации.
- При изменении параметра цепи очищаются, устаревшие результаты worker
  отсекаются сменой поколения. Верхний и нижний каналы не смешиваются.
- Допустимо 0…5; при текущих пяти подтверждениях UI ограничивает максимум 4.
  Также k не может превышать фазовый допуск и должен быть меньше числа
  подтверждений каждой включённой антенны. Невозможное сочетание отвергается
  до изменения настроек. При чтении несовместимого старого файла условие
  остаётся строгим и не разрешает событие.
- В AutoFreeze при включённой проверке добавлено `D2≥2` в существующий блок
  подтверждений. В снимке сохраняется `confirm_diversity` с threshold,
  distinct, required, ok; в статусе — `confirm_diversity0/1` и
  `diversity_rejected0/1` (число отклонённых полных окон, не число событий).
  Время в заголовке, обе антенны, линии шума и остальные подписи сохранены.
- Сохранение через портал и core согласует верхний ключ конфигурации и
  вложенный `tag_detection`; после перезапуска используется то же значение.
