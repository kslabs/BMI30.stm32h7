# Рост амплитуды между первым и последним подтверждением

Установлено только на M02 (`BMI30-E29805C7C`, serial `490df72e29805c7c`),
в текущую активную систему eMMC `/dev/mmcblk0p2`. Итоговый полный пакет:
`2026-10-21-1819`, манифест `2026-10-21-181950`.

В разделе обнаружения меток, перед защитой от одиночного импульса, добавлена
строка «Рост амплитуды подтверждений». Галочка включения и поле коэффициента
находятся **в одной строке**. Коэффициент по умолчанию **2,0**, галочка снята.
Изменения активируются обычной кнопкой сохранения и применения к Core.

После набора C последовательных подтверждений начало события разрешается,
если `последняя амплитуда >= первая амплитуда × коэффициент`. Проверка независима
для каждой антенны. Используются неокруглённые значения произведения в позициях
обнаруженных максимумов. Промежуточные амплитуды не обязаны расти монотонно.
Например, последовательность 1000 → 4000 → 2000 проходит при коэффициенте 2,0;
1000 → 1500 → 1999 не проходит.

При недостаточном росте проверяется следующее окно из C последовательных
подтверждений. Старая первая амплитуда постепенно выходит из окна. Пропуск
кандидата, разрыв кадров или сброс фазовой цепочки очищает её начало. При
включённой функции каждый разрешённый канал должен иметь не менее двух
подтверждений. Остальные фильтры остаются обязательными. После принятия
события действуют существующие правила HOLD, повторное удвоение не требуется.

Ключи конфигурации: `confirm_growth_enabled` и `confirm_growth_ratio`.
Коэффициент ограничен диапазоном 1–100. Портал, сохранённая конфигурация,
стартовая загрузка Core и API согласованы. Снятая галочка явно отправляет 0.
Изменение параметров очищает обе цепочки/HOLD и меняет поколение worker без
сброса накопленного шума. Диагностика API содержит первые/последние амплитуды,
полученное отношение и причину допуска или отказа; данные включены в снимок
события и шаги подтверждения. Проверка также добавлена в offline Player.

Программная проверка: 105 Python-тестов пройдены, 2 необязательных пропущены.
Включена 21 новая проверка: точная граница ×2, коэффициент пользователя,
скользящее окно, разрыв/пропуск/сброс фазы, независимые каналы, HOLD, сочетание
с разнообразием пиков, некорректные амплитуды, сохранение и загрузка настроек,
передача через Core и API. При OFF решения на 500 смешанных синтетических
кадрах совпали с прежним движком. Остальные проверки охватывают ширину,
разнообразие, свежесть пар, исходную защиту, геометрию и измерение шума.

Установленная форма отрисована реальными функциями портала. DOM-проверка
подтвердила общую строку для галочки и числа, значение 2,0, состояние OFF,
английские/русские подписи и подсказку, обратимость перевода и отправку обоих
состояний галочки. Это проверка разметки и DOM, без утверждения о визуальной
проверке в браузере пользователя.

Core/engine обновлены в `2026-10-21-1815`. Финальная правка расположения
элементов в `1819` обновила только портал и метаданные версии: Core не
перезапускался, PID `294926` сохранён. Его активные файлы по-прежнему имеют
суффикс `2026-10-21-1815`. Настройки сохранены побайтно при установке движка;
финальная правка портала также сохранила конфигурацию. На момент итоговой
проверки: STM32/Raspberry 16/12, подтверждения 5/5, исходная защита включена,
новый фильтр выключен, коэффициент 2,0.

После финальной установки M02 обработал 480 результатов за 10 секунд.
Прирост gap/duplicate/CRC/magic/ACK/worker overflow равен 0. Обе диагностики
нового фильтра сообщают `enabled=false`, `ok=true`, `reason=disabled`.
Реальные проходы и статистическое снижение ложных срабатываний пока не
сравнивались; для этого требуется одинаковый профиль и длительные OFF/ON записи.

Первая кандидатная версия `1812` была отклонена установочной проверкой из-за
отсутствующих полей в API Core. Автоматический откат и исходные хеши проверены;
кандидат убран из доступных пакетов в карантин, локальный архив помечен REJECTED.
Ошибка исправлена и покрыта отдельными проверками до установки `1815`.
