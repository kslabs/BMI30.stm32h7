# Измеренная RX-фаза: инструкция разработчику хоста

Прошивка **1.2.53** добавляет независимую оценку приёмной фазы каналов A и B.
Хост получает уже отфильтрованный результат **0° / 180°** и признак его
достоверности. Это результат обработки ADC; он не копируется из команды TX.
Существующие команды управления TX и формат потока ADC не изменены.

## Что показывает результат

`phase` относится к **чётным кадрам существующего `buffer_index`**. Для
нечётных кадров используется противоположная полярность: `(even_deg + 180) % 360`.
Детектор проверяет согласованность обеих чётностей. A и B оцениваются отдельно.
Нельзя подменять этот результат `GET_TX_PHASE`: локальный RX может принимать
сумму нескольких передатчиков, поэтому изменение TX не обязательно переворачивает RX.

Это экспериментальная бинарная классификация фазы звенения 6,25 кГц относительно
фиксированной оси 110° от начала ADC-кадра. Она не является калиброванным измерением
абсолютной фазы катушки или основной частоты 200 Гц. Амплитудный эталон и обучение
«текущее состояние считать нулём» не используются. Ось выбрана по исследованной
установке; после изменения аналогового тракта или частоты звенения нужна проверка.
После переподключения нельзя автоматически объявлять полученную фазу нулевой.

Не следует считать чётность кадра постоянным эквивалентом физического уровня
TX1/TX2: управление фазой и восстановление синхронизации могут менять это
соответствие. Подпись в UI: **«RX A, чётные: 0°»**, **«RX B, чётные: 180°»**.
Состояние/заданную фазу TX показывать отдельно.

## Как читать

USB Vendor **EP0 IN**, команда `GET_RX_PHASE = 0x4E`:

```python
raw = bytes(dev.ctrl_transfer(0xC0, 0x4E, 0, 0, 112, timeout=100))
```

`bmRequestType=0xC0`, `wValue=0`, `wIndex=0`, `wLength=112`.
Все многобайтовые числа little-endian. Ответ имеет сигнатуру **RXP1**, версию 1.
Команда только читает готовый снимок; расчёт во время USB-запроса не запускается.
Готовый Python-декодер: [vendor_rx_phase.py](vendor_rx_phase.py), функция
`decode_rx_phase(raw)`. Функция `read_phase(dev)` делает тот же запрос с timeout 500 мс;
для рабочего хоста выбирать timeout по его существующей очереди управления.

Опросить раз в секунду, при необходимости два раза в секунду. Использовать
существующего владельца USB и его очередь диагностических запросов низкого
приоритета. При занятости пропустить опрос. Не задерживать bulk-reader, обработку
ADC и UI ожиданием EP0; не удерживать общий lock потока во время ожидания.
Не вызывать `set_configuration`, reset, detach, STOP/START_STREAM ради диагностики.
На старой прошивке STALL/неподдержанная команда означает «RX-фаза недоступна»;
повторная проверка — после переподключения/обновления, без перезапуска потока.

## Формат ответа: 112 байт

| Смещение | Тип | Поле |
|---:|---|---|
| 0 | char[4] | `RXP1` |
| 4 | u8 | версия = 1 |
| 5 | u8 | число каналов = 2 |
| 6 | u16 | размер = 112 |
| 8 | u32 | `seq_begin`, чётный номер публикации |
| 12 | u32 | `uptime_ms` на момент публикации |
| 16 | u32 | поколение захвата ADC |
| 20 | u32 | число кадров, обработанных диагностикой |
| 24 | u32 | пропущенные попытки диагностического снимка; не потери ADC/USB |
| 28 | u32 | максимальные циклы одной порции фоновой работы |
| 32 | u32 | накопленные циклы фоновой работы, переполняются по модулю 2³² |
| 36 | u32 | время последнего обработанного диагностического кадра |
| 40 | 32 bytes | канал A |
| 72 | 32 bytes | канал B |
| 104 | u32 | детектор разрешён: 0/1 |
| 108 | u32 | `seq_end`, должен совпадать с `seq_begin` |

Циклы включают прерывания, пришедшие во время измеряемой порции, и являются
диагностической оценкой нагрузки, не точным профилем чистого времени алгоритма.

Внутри каждого 32-байтового канала:

| Смещение от канала | Тип | Поле |
|---:|---|---|
| 0 | u8 | `phase`: 0 → 0°, 1 → 180°, 255 → решения ещё нет |
| 1 | u8 | `valid`: текущее решение достоверно, 0/1 |
| 2 | u8 | `quality`: 0…100, показатель качества, не вероятность |
| 3 | u8 | флаги состояния, см. ниже |
| 4 | i16 | измеренный угол относительно фиксированной оси, 0,01° |
| 6 | u16 | согласованность нормированных векторов, 0…1000 |
| 8 | u16 | амплитуда выделенной составляющей в условных ADC-единицах |
| 10 | u16 | число принятых чётных кадров в окне |
| 12 | u16 | число принятых нечётных кадров в окне |
| 14 | u16 | доля отсчётов 0/65535 в раннем окне, 0…1000 |
| 16 | u32 | время последнего достоверного решения, мс |
| 20 | u32 | число подтверждённых изменений бинарной фазы |
| 24 | u16 | доля отсчётов 0/65535 в диагностической рабочей зоне, 0…1000 |
| 26 | u16 | минимум сырого ADC в диагностической рабочей зоне |
| 28 | u16 | максимум сырого ADC в диагностической рабочей зоне |
| 30 | u16 | размах `max-min` в этой зоне |

Флаги: `0x01` накопление; `0x02` слабый сигнал/недостаток пригодных кадров;
`0x04` неоднозначная фаза; `0x08` заметное ограничение раннего сигнала;
`0x10` устаревшие данные; `0x20` неподдерживаемый режим ADC.
`clipped` сам по себе не отменяет `valid`: ограничение допускается только при
выполнении остальных проверок. Метрика рабочей зоны не равна раннему ограничению.

## Правила отображения

1. Проверить длину, сигнатуру, версию, размер, `seq_begin == seq_end` и чётность
   sequence. Для основного текста использовать **только `phase`**, не округлять
   повторно поле угла на хосте.
2. При `enabled=1` и `valid=1` показать 0° или 180° отдельно для A и B.
   Накопление в STM32 занимает 1,5 с; при реальном переключении подтверждение
   может занять примерно 2–2,5 с, плюс задержка опроса хоста.
3. При `valid=0` сохранить последнее значение серым с подписью «уточняется»
   либо показать «—». Не выдавать сохранённую фазу за актуальное измерение.
   До первого решения `phase=255` всегда показывать «—».
4. Проверять свежесть локальными монотонными часами хоста: если в течение
   1,5 с нет нового sequence/uptime либо нет ответа, показать «нет свежих данных».
   Не вычислять свежесть только из двух полей одного застывшего пакета.
5. После смены поколения захвата, уменьшения uptime или переподключения
   сбросить кэш UI. При остановке/возобновлении потока не отправлять управляющих
   команд от имени индикатора RX-фазы.
6. В подробностях можно показать качество, возраст решения и ограничение
   рабочей зоны. Это диагностический индикатор; он не должен автоматически
   менять TX-фазу, усиление, синхронизацию или запускать аппаратные реакции.

Для текущей версии поддержан режим **600 отсчётов, 400 кадров/с, 240 квыб/с**.
Раннее окно — отсчёты `[20:240)`, дополнительные окна `[20:140)` и `[100:220)`.
Диагностическая рабочая зона **фиксирована `[300:500)`** и не отслеживает ROI,
который пользователь может изменить в интерфейсе хоста.

## Передача разработчику

Для интеграции достаточно этого документа и `vendor_rx_phase.py`.
Для отдельного диагностического запуска `python3 vendor_rx_phase.py` также
нужны PyUSB и лежащий рядом `vendor_tx_phase.py` (только выбор USB-устройства).
Изменять основной приём ADC и команды управления TX не требуется. Имеющийся
хост на Raspberry Pi в рамках этой задачи не редактируется и не перезапускается.
Результаты прошивки и испытаний: [RX_PHASE_1.2.53_RU.md](RX_PHASE_1.2.53_RU.md).
