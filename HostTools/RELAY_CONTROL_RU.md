# Независимое управление реле PC1 — FW 1.2.50

Реле активно при HIGH на PC1. Реле и внешняя адресная лента имеют независимые
команды, разрешения на хосте и таймеры. `LED_EVENT (0x35)`, выключение ленты,
стартовая демонстрация и системный WS2812 не включают и не выключают реле.
Прежнее автоматическое повторение ленты из FW 1.2.49 отменено.

## Правила хоста

Сначала вычислить условие срабатывания с учётом настроенного фотодатчика.
После этого независимо проверить два выключателя:

- Лента разрешена: отправить прежний `LED_EVENT` с её паттерном и длительностью.
- Реле разрешено: отправить `RELAY_EVENT` с настроенной длительностью реле,
  даже если лента выключена или её паттерн равен OFF.

Не размещать отправку команды реле внутри ветки `if adrLed_enabled`.
Снятие разрешения реле: немедленно отправить `SET_RELAY_ENABLE=0`.
Выключение ленты: отправить прежний `LED_EVENT` с pattern=0, не менять реле.

Разрешение реле хранится только в RAM, при старте равно 0. Инициализация хоста:
прочитать `RLY1` для проверки поддержки, отправить запрет, затем применить
сохранённое в конфигурации хоста разрешение. Повторять при reset/reconnect.
Разрешение само не включает выход и не воспроизводит пропущенные события.
Повторная отправка разрешения 1 не прерывает уже работающий таймер/тест.

## Команды

Vendor bulk OUT: IF#2, EP 0x03, пакет `[opcode | payload]`.
Предпочтительный путь при активном потоке — EP0 Vendor Device OUT `bmRequestType=0x40`,
`wIndex=0`, `bRequest=opcode`; data stage содержит только payload, без opcode.
Для data stage использовать `wValue=0`. Все многобайтные числа little-endian.

| Код | Команда | Payload | Действие |
|---|---|---|---|
| 0x4A | SET_RELAY_ENABLE | ровно u8 0/1 | 0 запрещает и немедленно выключает; 1 разрешает будущие события/тест |
| 0x4B | RELAY_EVENT | ровно u32 duration_ms LE | 0 немедленно выключает, включая тест; 1..2147483647 включает на заданное время, если разрешено |
| 0x4C | GET_RELAY_STATUS | только EP0 IN | ответ RLY1, 20 байт |
| 0x4D | SET_RELAY_TEST | ровно u8 0/1 | 1 удерживает HIGH до остановки, если разрешено; 0 немедленно выключает любой режим |

EP0 OUT без data stage также поддержан: 0x4A/0x4D принимают `wValue=0/1`,
0x4B принимает `wValue=0..65535` миллисекунд. Для большей длительности нужен
четырёхбайтовый data stage. 0x4C: `bmRequestType=0xC0`, `wValue=wIndex=0`,
`wLength=20` (значение меньше 20 вызывает STALL).

Некорректные длины/значения не меняют состояние: EP0 возвращает STALL,
bulk игнорирует команду. Bulk не имеет отдельного ACK — проверять через 0x4C.
При data stage параметр берётся из payload; wValue не используется.

Каждый новый RELAY_EVENT перезапускает таймер от момента обработки команды,
а не прибавляет время к старому. Длительность реле не связана с длительностью
ленты. При запрете положительные события отбрасываются, не накапливаются.
Диапазон u32 ограничен 0x7FFFFFFF для корректного сравнения при переполнении
миллисекундного счётчика; большие значения отклоняются, не обрезаются.

## Кнопка длительного теста

«Тест реле»: при разрешённом реле отправить `SET_RELAY_TEST=1`.
«Стоп»: отправить `SET_RELAY_TEST=0` или `RELAY_EVENT=0`.
Не отправлять тест как короткие повторяющиеся LED_EVENT.
Тест работает независимо от фотодатчика и ленты — это явная ручная проверка.
Он заменяет текущий таймер; положительные RELAY_EVENT во время теста
игнорируются. После «Стоп» старый таймер не возобновляется.
Снятие разрешения отменяет и тест, и таймер. Разрешение 1 не восстанавливает тест.

После перезапуска STM32 и USB reset/deconfiguration реле запрещено и выключено.
При завершении/переподключении приложения отправлять запрет; не восстанавливать
held test автоматически. Само закрытие приложения при сохранённой USB-связи не
является командой остановки: тест без тайм-аута продолжается до явного STOP.
Если кнопка должна тестировать заданное время, использовать RELAY_EVENT вместо
режима удержания, например 180000 мс для трёх минут.

## RLY1 — 20 байт

| Смещение | Размер | Значение |
|---|---|---|
| 0 | 4 | ASCII RLY1 |
| 4 | 1 | Версия формата 1 |
| 5 | 1 | enabled, разрешение 0/1 |
| 6 | 1 | active, выходной регистр PC1 0/1 |
| 7 | 1 | pc1, входное чтение PC1 0/1 |
| 8 | 1 | mode: 0=выключено, 1=таймер, 2=длительный тест |
| 9 | 3 | Резерв, 0 |
| 12 | 4 | remaining_ms LE; 0 при OFF, 0xFFFFFFFF при тесте |
| 16 | 4 | max_duration_ms LE = 0x7FFFFFFF |

Значение PC1 не подтверждает положение механических контактов реле.
Чтение статуса доступно во время ADC/USB stream без изменения его конфигурации.

## Проверка через UART / готовый Python-клиент

`RELAY 0|1`, `RELEVT milliseconds`, `RELTEST 0|1` проходят через тот же обработчик
Vendor-команд. `OPTIC` показывает `relay_enabled`, `relay_mode`,
`relay_remaining_ms`, `relay` и `pc1`. Эти UART-команды не заменяют EP0 в хосте.

Примеры клиента [vendor_relay.py](vendor_relay.py):

```text
python HostTools/vendor_relay.py --enable 1
python HostTools/vendor_relay.py --pulse-ms 2500
python HostTools/vendor_relay.py --pulse-ms 180000
python HostTools/vendor_relay.py --test 1
python HostTools/vendor_relay.py --stop
python HostTools/vendor_relay.py --enable 0
```

Без параметров действий клиент только читает RLY1. При нескольких USB-устройствах
нужно указать `--serial` или `--index`. Разрешение после ручных тестов возвращать
к настройке пользователя. Английская инструкция: [RELAY_HOST_INTEGRATION_EN.md](RELAY_HOST_INTEGRATION_EN.md).
