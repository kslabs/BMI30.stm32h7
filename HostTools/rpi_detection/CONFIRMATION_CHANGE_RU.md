# Изменение амплитуды подтверждений

В строке «Изменение амплитуды подтверждений» две независимые галочки ↑ и ↓
и один общий коэффициент k (по умолчанию 2,0; диапазон 1…100).

| ↑ | ↓ | Условие принятия полного окна |
|---|---|---|
| Нет | Нет | Дополнительная проверка отключена |
| Да | Нет | Последняя амплитуда ≥ первая × k |
| Нет | Да | Первая амплитуда ≥ последняя × k |
| Да | Да | Выполняется любое из двух условий |

Берутся неокруглённые амплитуды произведения в позициях первого и последнего
обнаруженных пиков полного окна последовательных подтверждений. Промежуточные
пики не обязаны изменяться монотонно. Проверка независима для каждой антенны;
для включённой проверки нужно не менее двух подтверждений. Изменение этого
фильтра не заменяет основные проверки детектора и прежние правила HOLD.
После отказа окно сдвигается; разрыв, промах и сброс фазы прерывают цепочку.
Смена направления или коэффициента сбрасывает обе цепочки/HOLD и поколение
обработчика, сохраняя накопленную оценку шума.

Основной параметр конфигурации/API — `confirm_change_mode`:
`up`, `down`, `either`, `off`. В форме отправляются два поля
`confirm_change_up` / `confirm_change_down`; скрытые значения 0 обеспечивают
явное выключение при снятии обеих галочек. Канонический режим вычисляется
на сервере, передаётся Core и сохраняется вместе с настройками детектора.

Коэффициент хранится в прежнем единственном поле `confirm_growth_ratio`,
чтобы сохранить существующие значения на каждом приборе. Прежнее
`confirm_growth_enabled` без режима преобразуется: true → up, false → off.
Явный `confirm_change_mode`, включая off, имеет приоритет над старым флагом.
Старый API-флаг возвращается как признак включения любого режима проверки;
для определения направления следует читать `confirm_change_mode`.
При записи нового режима обе копии настроек (корень и `tag_detection`)
синхронизируются. Частичная запись только коэффициента сохраняет направление.
Установка пакета не переписывает конфигурацию: миграция применяется при
чтении и сохраняется при обычном сохранении настроек пользователем.

Патчер `patch_confirmation_change.py` расширяет полный выпуск
`2026-10-23-1435`, сохраняя служебные Wi-Fi/Bluetooth и совместимость
с отсутствующими дополнительными функциями старой STM32. Фильтр исполняется
на Raspberry; обновления STM32 для него не требуется.

Проверки: 21 прежняя проверка роста/окон/HOLD/сохранения и 11 новых проверок
направлений, точных границ, обоих каналов, сброса при смене направления,
миграции, четырёх сочетаний галочек и Core API. DOM-проверка выполняет
настоящий скрипт локализации фактически отрендеренной формы: одна строка,
две галочки, один коэффициент, четыре сочетания отправки, подписи и подсказка
на русском/английском. Эти проверки не являются физическим испытанием меток.
