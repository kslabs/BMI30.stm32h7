# SET_DC_SPEED (0x1F)

STM32 имеет один постоянно работающий процесс DC-компенсации. Единственный runtime-параметр приходит от RPI:

```text
Bulk OUT: 1F <settle_ms:uint32 little-endian>
```

- Полный пакет строго 5 байт.
- Диапазон `settle_ms`: `0..86400000`.
- `0` выключает обучение, но сохранённая DC-поправка продолжает применяться.
- `1` — максимально быстрая компенсация (1 мс); `1000` = 1 секунда.
- Чем больше ненулевое значение, тем медленнее адаптация.
- Ненулевое значение действует постоянно до следующей команды.
- После reset значение равно `0`; RPI отправляет нужную скорость при startup/reconnect.
- USB START/STOP и перезапуск ADC не сбрасывают скорость; обучение продолжается в фоне даже без USB stream.

RPI не должен переносить в этот пакет старый `WORK` default `100000`. В новом
протоколе `100000` означает ровно 100 секунд. Для выбранной пользователем
скорости 1 секунда полный пакет должен быть `1F E8 03 00 00`. Каждое изменение
UI немедленно отправляет новый пакет, а reconnect повторяет последнее явно
выбранное значение.

Шаг адаптивен для каждой точки:
`corr[i] = abs(error[i]) * 8 * dt_ms / settle_ms`, с ограничением до deadband 16 LSB. Чем больше отклонение, тем больше
коррекция; возле virtual zero она плавно уменьшается. Дробный Q16-остаток хранится для каждой
точки, поэтому малый шаг не теряется. Максимальная ошибка входит в deadband примерно за
`0.95 * settle_ms`, ошибка 1000 LSB — примерно за `0.52 * settle_ms`. Для `settle_ms=1000`
и `dt=10 ms` начальные шаги составляют около 2620 и 79 LSB соответственно.

Python:

```python
import struct
from usb_vendor.usb_stream import USBStream

stream = USBStream()
stream.send_cmd(0x1F, struct.pack("<I", 1_000))  # примерно 1 секунда
```

Старые `SET_DC_ADAPT (0x1B)`, `CALIB_DC_FAST (0x1E)` и много-параметрический `SET_DC_CONFIG` удалены.

COM-команда `OPTIC` позволяет проверить путь команды без Vendor IN:
`dc_ms` показывает принятое значение, `dc_cmd`/`dc_rej` — принятые и
отклонённые пакеты, а `dc_calls`, `dc_updates`, `dc_dt_ms`, `dc_maxerr` и
`dc_maxcorr` — фактическую работу адаптации. После reset ожидается
`dc_ms=0 dc_cmd=0`; любое последующее `dc_cmd>0` означает, что STM32 получила
пакет управления от USB-хоста.
