Переносимая USB-система определяет текущую плату по физическому serial CM5
из Device Tree или /proc/cpuinfo. Runtime ID — BMI30- и последние 9 hex символов
serial в верхнем регистре; hostname и прежний id из конфигурации не подменяют
аппаратную identity. Серийный номер USB-носителя в продуктовой проверке не нужен.
Network/group/recovery используют текущую аппаратную identity. Службы policy
и recovery больше не содержат статический --expected-host. Явный expected-host
остаётся доступен для адресной проверки при ручном обслуживании конкретной платы.
Ошибочный или недоступный аппаратный serial прекращает работу до сетевых действий.

Пакет добавляет установку/откат публичных portable assets через канонический
server updater, builder и switcher. Проверяются allowlist и хеши; сетевые настройки,
fleet credentials, аппаратные credentials, калибровка и рабочие режимы сохраняются.
Доступ к существующей приватной конфигурации не расширяется: 0600/0640 сохраняются,
обычный runtime-файл 0644 ограничивается до 0640; чужой symlink отклоняется.
Обновлён заголовок портала: основная версия STM32 берётся из его текущего runtime
firmware, а build date/time отображаются отдельно при наличии этих данных.
Прошивка STM32 остаётся 1.2.55; её проверенный архив — FirmwareReleases/STM32/1.2.55.

source-inputs.tar.gz содержит точные публичные исходники финального пакета,
service units, release headers, utilities и входы тестов с отдельными SHA256.
Приватные конфигурации, ключи, токены, runtime state и сырые диагностические логи
в архив исходников и evidence не включены. Официальный пакет сохранён целиком:
host/bmi30_config.json в нём — пустой шаблон {}, не конфигурация пользователя.
RTC Python environment сохраняется на целевом устройстве и не архивируется здесь.

Проверки подготовленного кода: 55 ARM network/group/stability/recovery/identity
тестов, 6 тестов прав/конфигурации, 7 asset install/rollback/allowlist тестов,
6 Python и 8 JavaScript тестов отображения версии, Bash syntax builder/switcher.
publication.json, validation.json и source-inputs.json разделяют публикацию,
подготовительные проверки и точные исходные входы. Это не подтверждение загрузки
каждой системы с eMMC/USB или физической переносимости между платами.
