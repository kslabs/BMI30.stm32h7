# Исходная база BMI30 — 12 ноября 2026

Для дальнейшей разработки используется одна основная ветка `main`. Карта ниже
разделяет рабочие исходники, неизменяемые выпуски и локальные исторические материалы.
Пользователь разрешил очистку локального репозитория и GitHub с архивированием
прежних версий. Приборы, серверные публикации, загрузочные носители и настройки
устройств в эту работу не входят. Изменение этой карты само по себе ничего
на GitHub не публикует.

## Рабочие исходники

| Часть | Основной путь и назначение |
|---|---|
| STM32 | Корневые `Core/`, `USB_DEVICE/`, `Drivers/`, `Middlewares/`, startup и linker-файлы: полный исходный срез **1.2.59-host-tx-lcd**, восстановленный из frozen source archive этого выпуска. Старое содержимое `Debug/` не является исходной базой. |
| SDK STM32 | `SDK/STM32Cube_FW_H7_V1.12.1/`: зависимости для автономной сборки без скачивания SDK. |
| Контроль сборки STM32 | `BuildSupport/STM32/`: frozen builder, `build-spec.json` и манифесты входных файлов. Запуск — `python scripts/build_stm32.py`. |
| Raspberry Pi | `Runtime/RaspberryPi/`: все **173 файла** опубликованного архива **2026-11-06-151000**, с сохранением путей внутри `Documents/` и точного содержимого. |
| Контроль Raspberry Pi | `python scripts/verify_raspberry_baseline.py`: сравнение с архивом 151000, проверка **158** записей bundle `SHA256SUMS` и разрешения активных Core, Engine и GUI. |
| XM125 | `RadarFirmware/XM125/`: самостоятельный проект; эта очистка его реализацию не меняет. |

`scripts/build_stm32.py` копирует перечисленные в манифесте исходники и frozen builder
в новый каталог `.tmp/stm32-baseline-*/`, затем выполняет автономную сборку. Проверка
контролирует закреплённые входные файлы, SDK и компилятор и требует побайтного
совпадения BIN с выпуском 1.2.59. Результаты и `build-report.json` остаются в `.tmp/`.
Команда не прошивает устройства и не использует сеть.

Эти команды проверяют закреплённую базу. После намеренного изменения исходников
несовпадение ожидаемо: спецификацию сборки, манифесты, версию и эталон нового
выпуска обновляют отдельным осмысленным шагом. Ослаблять проверки или обходить
их ради успешного результата нельзя. В неизменяемых каталогах прежних выпусков
эталоны не перезаписываются.

входят в сохранённый комплект и покрыты контрольными суммами. Переписывать
исторические имена и вложенный указатель только ради одинаковых дат не требуется.

## История и восстановление

Для очистки **12 ноября 2026 года** пользователь установил три уровня хранения
сохранённых версий локально и на GitHub:

| Дата версии | Назначение | Исторические каталоги выпусков |
|---|---|---|
| С `2026-10-12` включительно | Версии для отката | `archives/rollback-releases/<семейство>/<версия>/` |
| `2026-09-12` — `2026-10-11` включительно | Архив только для восстановления | `archives/archive-releases/<семейство>/<версия>.zip` |
| Ранее `2026-09-12` | Удаление всех отдельно сохранённых версий | Не сохраняются в явных резервных копиях, release payloads или тегах |

Корневая рабочая база остаётся последней версией, указанной выше. Старые даты
отдельных файлов внутри её манифестов не превращают компоненты текущего выпуска
в самостоятельные старые версии. Каталоги отката и архива исключены правилами
Git и не являются параллельными рабочими исходниками.

Полные `all-refs.bundle` и `worktree-before.zip` используются только как временная
защита на время очистки. После проверки отдельных наборов для отката и архива
эти полные снимки удаляются, чтобы в явных резервных копиях не осталось версий
старше двух месяцев. `refs-before.txt`, `worktree-manifest.json` и
`backup-verification.json` могут сохраняться как учёт состава и проверки;
они не заменяют сохранённые исходники или release payloads.

Все прежние локальные и удалённые ветки закрываются. Их исходные tips
классифицируются по дате коммита: с `2026-10-12` — для отката,
`2026-09-12` — `2026-10-11` — архив только для восстановления.
Соответствующие теги сохраняются локально и публикуются на GitHub.
Существующие теги выпусков и версий ранее `2026-09-12` удаляются локально и
на GitHub, без отдельного постоянного полного bundle со старыми версиями.

Эта политика относится к отдельным версиям, ссылкам и артефактам. Обычная
история коммитов Git принудительно не переписывается: удаление тегов и веток
не стирает старые коммиты из родительской истории текущей `main`.
Новая `main` сохраняет прежнюю `origin/main` родителем посредством
явного объединения историй со стратегией `ours`: рабочее дерево остаётся новой
исходной базой, а публикация `main` возможна обычным fast-forward без force push.
Прежние удалённые ветки закрывают только после повторного чтения с GitHub и
проверки опубликованных архивных тегов и новой `main`.

Для восстановления выбирают нужную версию из набора отката либо архива и
сверяют её манифест и контрольные суммы. Для bundle сначала выполняют
`git bundle verify` и `git bundle list-heads` с путём к выбранному файлу,
затем `git clone` в **новый, ещё не существующий каталог**. ZIP с рабочими
файлами также распаковывают через `Expand-Archive` в отдельный новый каталог,
без перезаписи текущей рабочей копии. Клонирование bundle восстанавливает
сохранённую историю; ZIP или каталог release payloads — соответствующие файлы.

226 входов SDK и полный Raspberry runtime — без расхождений. Вложенные атрибуты
TinyUSB учитываются явным `eol=crlf`; остальные frozen-файлы сохраняются побайтно.

Учтены **5 текущих**, **116 для отката**, **53 архивных** набора и **1 удалённый**
старый выпуск. Все **11531** сохраняемых файлов из предварительного манифеста
проверены по SHA256, архивы дополнительно проверены по CRC и составу.
[Учёт пакетов](../FirmwareReleases/retention-catalog.json).
Предыдущая незакоммиченная исходная база сохранена в
`archives/rollback-releases/WorkingTree/2026-11-12-before-cleanup.zip`
с манифестом и повторной проверкой SHA256.

Теги Git за второй месяц имеют префикс `archive/`, за первый — `rollback/`.
Точка новой исходной базы — `baseline/2026-11-12`. План ссылок и исходные OID:
[учёт Git](git-retention-2026-11-12.json). Итоговый отчёт публикации и закрытия
ссылок — `docs/validation/repository-cleanup-2026-11-12.json`.
Локальные payload-архивы не загружаются на GitHub; там сохраняются существующие
в Git срезы исходников и новая основная база. Обычная история коммитов сохраняется.

Приборы в этой работе не прошивались и не перезапускались.
